# Engineering workflow
Use iterative SDLC: discovery, requirements, design, implementation, verification, release, operation. Each issue identifies requirement IDs, acceptance criteria, risk and test plan. Branch from main; small commits; PR with linked requirements, test evidence, migration/rollback plan and documentation. CI must pass before merge. Independent review where available; solo development records self-review and residual risk. No claim of branch protection until configured. Use semantic versioning for OS releases; changelog and release notes. Track defects by severity; critical security or data-loss defects block release. No production customer data in tests.
